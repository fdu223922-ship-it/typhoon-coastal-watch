# 沿海台风通：台风实况与分级预警网站计划书

版本：v0.1 ｜ 编写日期：2026-09-21 ｜ 阶段：立项规划

本文是产品与交付计划，未代表网站或数据服务已经实现。参考来源见[数据来源与核验记录](数据来源与核验记录.md)。

## 一、项目目标与服务范围

建设一个以手机使用为主的网站，让沿海居民在约十秒内找到台风名称、当前位置、移动趋势、中心风力和所在地官方预警，并能继续查看官方防御指引。

主要用户包括沿海家庭、老年居民、通勤者和社区工作人员。采用大字号、短句和清楚的更新时间；不要求用户懂经纬度或气象术语。

首期默认服务中国大陆沿海地区，优先选一个已取得数据授权的沿海城市及其区县试点，架构支持后续扩展。具体试点城市、预算和运营责任人尚待确定。港澳台及其他地区采用各自预警体系，应单独规划接入，不能直接套用大陆四色信号。

### 成功指标（拟定验收目标）

- 5—8 名目标用户试用时，至少 80% 能在十秒内找到四项台风信息及所选地区预警。
- 所有实况、预报和预警均可追溯至来源与业务时间；数据缺失有明确提示。
- 在 320px、390px 和 1440px 宽度下，核心信息完整可读，无页面横向溢出。
- 地图加载失败或用户拒绝定位时，仍可手动选择地区并查看文字信息。

## 二、首期产品范围

| 优先级 | 功能 | 居民看到的结果 |
| --- | --- | --- |
| P0 | 台风名称与编号 | 中文名、英文名、编号；未命名系统使用来源给出的编号，不虚构名称 |
| P0 | 中心位置 | 海域或官方参考位置、经纬度、观测时间；地理描述优先于专业数字 |
| P0 | 移动趋势 | 官方移动方向、速度或速度范围，以及最新一轮预报路径 |
| P0 | 风力与强度 | 中心附近最大风力（级）、风速（米/秒）、来源强度等级；气压可作补充 |
| P0 | 所在地官方预警 | 手动选市/区县，显示覆盖该地区的信号、机构、时间、原文和防御指引 |
| P0 | 路径地图 | 已发生路径、最新定位点、未来预报路径分别标注，并提供文字列表替代 |
| P0 | 状态与来源 | 展示数据时间、来源链接、正常/延迟/不可用等状态以及重试入口 |
| P0 | 多台风与无台风状态 | 可切换台风；仅在来源明确确认时显示“当前无活跃台风” |
| P1 | 常用地区 | 在本机保存关注地区，默认不要求注册 |
| P1 | 风圈及地方风雨信息 | 仅接入有授权且口径明确的数据；当地风力与中心风力分栏 |
| P1 | 站内更新提示 | 提醒当前打开页面的用户预警发生变化，不宣称离线必达 |
| P2 | 后续扩展 | 浏览器推送、短信或其他订阅渠道、历史回放、海浪与风暴潮独立预警 |

首期不开发自主气象预测、撤离路线推荐、避难场所实时容量或自动停课停工判断。官方转移通知、交通安排等在获得可靠来源后以独立信息卡呈现，不能根据预警颜色自行推断。

## 三、信息表达与页面结构

### 首页：先看本地影响，再看台风概况

1. 顶部为“关注地区”选择器，默认提示选择地区；定位是可选功能，使用前由用户主动授权。
2. 其下为本地预警卡：信号名称、色块加文字、覆盖范围、发布机构、发布时间、状态和原文入口。
3. 台风切换栏支持多台风，保留用户选择；不擅自把最近的台风称为“最危险”。
4. 四张概要卡分别回答：叫什么、在哪里、往哪走、风力多大；同时显示该轮业务时间。
5. 路径地图区标注观测点与预报点，带图例、时间轴和可展开的文字表格。
6. 底部展示官方防御指引、来源、更新说明和数据异常提示。

### 台风详情与预警详情

- 台风详情：历史定位点、最新预报批次、强度变化和可获得的风圈数据。
- 预警详情：完整官方内容、发布与更新记录、区域以及解除/到期情况。
- 数据说明：解释“中心风力”“当地风力”“移动速度”和“预报路径”，说明不同机构产品不能混作同一条预报。

### 易读与无障碍要求

- 主信息优先使用中文短句，正文建议不小于 16px，触控区域建议至少 44px。
- 颜色必须配文字、图标和状态，黄色使用足够深的文字；不靠红绿区分状态。
- 支持键盘导航、可见焦点、屏幕阅读器和减少动态效果设置。
- 台风强度的地图图例与预警颜色图例分别命名；不让路径点颜色看起来像本地预警。
- “距所选地点的估算距离”只能作为地理参考；不得写成安全距离、倒计时或抵达时间。

## 四、分级预警方案

### 4.1 展示已有的官方信号

本项目的“添加分级预警”指接收并展示官方发布的信号。国家预警信号办法包含蓝、黄、橙、红四级；地方允许采用不同标准，中央与地方产品也需区分。[中国气象局官方办法及附件](https://www.cma.gov.cn/zfxxgk/gknr/flfgbz/gz/202005/P020220628619411458474.pdf)

以下仅作为国家附件的科普摘要，不作为本系统自动判定规则。所列风力指受影响沿海或陆地，不是台风中心附近最大风力：

| 信号 | 时间窗口 | 平均风力 / 阵风门槛（满足其一） |
| --- | --- | --- |
| 蓝色 | 24 小时 | 6 级及以上 / 8 级及以上 |
| 黄色 | 24 小时 | 8 级及以上 / 10 级及以上 |
| 橙色 | 12 小时 | 10 级及以上 / 12 级及以上 |
| 红色 | 6 小时 | 12 级及以上 / 14 级及以上 |

上述条件涉及可能或已经受热带气旋影响以及风力可能持续的情形，完整条件以来源附件为准。广东地方规定另含白色台风信号，因此地区配置必须保留本地原始信号，不能强行压缩成四色。[广东规定官方页面](https://weather.sz.gov.cn/szsqxjwzgkml/szsqxjwzgkml/zcfgjzcjd/zcfg/fljzgl/content/post_5614517.html)

### 4.2 区域匹配和状态处理

- 以官方行政区域代码或发布的影响范围匹配用户选择；支持上级预警覆盖下级地区。来源没有区县细节时，清楚写明覆盖精度。
- 全国性台风预警放在“全国台风形势”；不自动把它转换成每个城市的本地信号。
- 同区域、同灾种的更新按官方事件 ID、发布机构和修订关系处理。不同机构信号并列注明，不单凭最新时间或最高颜色覆盖所有信息。
- 存储首次发布、升级、降级、继续、解除及明确到期记录。只有官方解除或明确有效期结束，才能改变相应业务状态。
- 来源请求失败、空结果或采集超时不能当作“预警解除”。过期快照移入“历史信息，当前状态待核实”，不继续作为有效预警推送。
- 页面区分“该地区暂无有效预警”“该地区尚未覆盖”“数据暂不可用”，均不表述为“安全”。

### 4.3 防御信息

预警详情保留官方完整防御指引。首页可以提取有来源的阅读提示，但须单独标注且不改变原文含义。停课、停航、转移等执行信息以适用地区主管部门公告为准；台风预警与暴雨、海浪、风暴潮等信息分开显示。

## 五、数据来源与更新策略

### 5.1 数据接入原则

台风实况和预报优先评估中央气象台或获得合法转授权的服务；地方预警优先评估试点地区气象部门提供的正式渠道。已核验中央气象台台风快讯包含名称、编号、位置、强度、风力、气压、移动趋势等字段。[台风快讯](https://www.nmc.cn/publish/typhoon/typhoon_new.html)

该网页同时提示数据使用需要授权。目前尚未确定可用 API、商用/公开展示许可、调用额度、报价或服务承诺。不得把网页地址、搜索摘要或未公开的内部接口直接认定为生产数据接口。授权未落实时，原型仅用明确标注的模拟数据，保留官方查询入口。

### 5.2 建议数据模型

| 对象 | 必需或关键字段 |
| --- | --- |
| 台风 | 内部 ID、来源编号与年份、中文名/英文名、生命周期、数据源 |
| 实况点 | 台风 ID、观测时间、经纬度及坐标系、风速及平均时段口径、风力等级、气压、参考位置、来源发布时间 |
| 预报批次 | 机构、发布时间、批次 ID；各预报点的有效时间、位置、强度、移动方向和速度范围 |
| 预警 | 官方 ID、修订关系、机构、灾种、原始等级、规则地区、区域、原文、发布时间、有效期、解除时间、原文链接 |
| 数据状态 | 采集时间、最近成功时间、预计下次更新时间、完整性、正常/延迟/不可用、异常原因 |

缺失值用 `null` 和说明表达，不补成 0。内部保存带时区的时间，页面默认北京时间并写出时区。实况与预报不可混合；不同机构的最大风速平均时段可能不同，不能无说明地比较或转换。

### 5.3 更新、缓存和容错（工程目标，待供应商确认）

- 采集任务按来源许可与发布周期运行，优先使用官方推送或标准接口；拟定轮询间隔 1—5 分钟，仅在额度允许时启用。
- 页面每 60—120 秒请求本站服务并支持手动刷新；轮询频率不代表官方每分钟产生新观测。
- 有下次发布时间时按该时间加合理宽限判断延迟；否则按经确认的产品周期配置，不对所有产品统一套用十分钟过期规则。
- 预警订阅流的健康状态单独监测；不能仅因一条持续有效预警很久未修订就认定其失效。
- 重试使用退避策略，缓存最近成功快照。明确显示快照业务时间及状态，页面刷新不得伪装成新观测。
- 主备源切换须保留机构标识、坐标系、批次和单位，不能拼接成一条看似连续的官方预报。
- 无活跃台风时仍检查所在地预警；台风消散或停止编号并不自动解除所有灾害预警。

## 六、技术与运行方案

以下为拟议架构，不是当前已有实现；具体版本在开发时核验并锁定。

- 前端：Vue 3、Vite、TypeScript，响应式网页；地图组件在确认底图许可和坐标系后选择。
- 后端：Node.js 数据适配与只读 API，负责鉴权、标准化、缓存、限流和健康检查；密钥不进入浏览器。
- 存储：小规模试点可用 SQLite 保存预警修订和采集状态，扩展时再评估 PostgreSQL；原始资料留存须符合授权范围。
- 基础设施：静态资源与数据服务分别部署，使用 HTTPS、日志、错误监控和备份；最终托管平台待选。
- 地图：使用有公开展示许可的底图，按服务要求处理坐标；上线前核验地图使用、标注和适用地区要求。
- 定位与隐私：默认手动选地区；精确定位仅临时用于地区匹配，不默认保存到服务端或公开日志。

```mermaid
flowchart LR
    A[经授权的台风与预警数据] --> B[采集任务与校验]
    B --> C[标准化数据与版本记录]
    C --> D[缓存与只读 API]
    D --> E[手机与桌面网页]
    B --> F[延迟和失败监控]
    F --> G[运营维护人员]
```

运维应关注上游失败率、数据延迟、预警处理延迟、API 错误和访问突增。出现严重错配或错误数据时，可关闭受影响模块、显示故障状态和官方查询入口，并保留排查记录。

## 七、实施排期与投入

按 1 名前后端开发主力、兼职设计/测试和一名内容审核责任人估算，MVP 约 4 周、开发主力约 20 个工作日。该估算以数据授权和接口及时可用为前提，采购审批及外部审核不计入承诺工期。

| 阶段 | 时间 | 主要交付物 | 完成条件 |
| --- | --- | --- | --- |
| 立项与数据验证 | 第 1 周 | 试点范围、接口清单、字段样本、手机版线框图 | 确认数据使用权、预警覆盖及地方规则；否则只推进演示原型 |
| 数据与基础页面 | 第 2 周 | 数据适配、状态 API、四项信息卡、地区选择 | 字段、单位、时区与来源逐项对照通过 |
| 路径与预警 | 第 3 周 | 路径地图、预警状态记录、详情页、异常降级 | 多台风、区域匹配、升级/解除及来源异常用例通过 |
| 验收与试运行 | 第 4 周 | 移动端优化、用户试用、监控与上线清单 | 完成验收并明确运营责任、应急联系人和回退办法 |

费用按以下项目立项询价：数据接口授权、地图用量、服务器与流量、域名、监控备份、开发维护；若增加短信或商业通知另计。当前无供应商报价，不给出未经核实的固定月费。预留约 20% 的工时用于数据和兼容性风险。

## 八、验收标准

| 场景 | 必须达到的结果 |
| --- | --- |
| 四项核心信息 | 和同一来源、同一业务时次逐项一致，缺失字段明确标注 |
| 地区预警 | 区县与上级覆盖正确；显示机构、原始级别、发布时间及完整原文入口 |
| 地方差异 | 白色信号等地区特有规则正确展示，不被硬映射成蓝色 |
| 状态变化 | 发布、继续、升级、降级、解除、明确到期可重放；旧修订不覆盖新修订 |
| 断网与失效 | 接口超时、空响应、过期、地图失败均有明确状态，不出现“暂无预警”等错误结论 |
| 路径语义 | 实况与预测可区分，显示预报机构和批次；不虚构概率范围或登陆倒计时 |
| 多台风及空态 | 切换不串数据；来源确认无台风和数据不可用具有不同文案 |
| 手机与无障碍 | 320/390/1440px 布局、键盘、焦点、文字替代和颜色对比通过检查 |
| 更新速度 | 若供应商时效支持，上游数据可获取后五分钟内进入本站；按采集日志验证 |
| 性能与承载 | 试点约定测试网络下核心文字三秒内可见；按试点规模设负载测试值，地图延后加载 |
| 隐私与发布 | 浏览器包和公开仓库无密钥，拒绝定位仍可用，演示数据不会进入正式服务 |

正式发布前至少完成一次完整的台风与预警事件回放，以及上游故障和恢复演练。试运行表现不等于长期可用性承诺。

## 九、主要风险与应对

| 风险 | 应对与责任角色 |
| --- | --- |
| 数据许可或覆盖不足 | 产品负责人先确认授权和试点范围；未落实时不开放实况模式 |
| 预警错配或错把断流当解除 | 开发人员实现版本记录与区域校验，内容审核人员检查官方原文 |
| 路径给居民造成确定性误解 | 明确实况/预报差别，只展示来源给出的不确定性说明 |
| 台风期间流量增长或断网 | 缓存、轻量文字视图、限流与故障提示；运维提前演练 |
| 单看台风风力忽略其他灾害 | 预留暴雨、海浪和风暴潮入口，分别说明数据覆盖情况 |
| 长期无人维护 | 上线前指定值守与更正流程；无人维护时暂停实况服务而非静默运行 |
