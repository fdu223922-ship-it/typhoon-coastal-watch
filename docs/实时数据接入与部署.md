# 实时数据接入与 GitHub Pages 部署

## 2026-09-21 已核验来源

来源页面：https://bmxx.swj.sh.gov.cn/typhoon/ （上海市水务局台风路径发布系统）。通过该站页面脚本确认并实际请求以下公开端点：

- `https://bmxx.swj.sh.gov.cn/netskip-datax-typhoon/weather/getTfByYear?year=2026`
- `https://bmxx.swj.sh.gov.cn/netskip-datax-typhoon/weather/getTfDetail?tfbh=202625`

请求无需登录或密钥。按当前北京时间年份及上一年读取列表，只为 `is_current=1` 的台风抓取详情，避免批量下载历史记录。实际读取到杜鹃（202625）；2026-09-21 17:00 北京时间定位为 34.5°N、140.5°E，风力 12 级，风速 33 m/s，移速 57 km/h，移向东北东，气压 970 hPa。这是核验时快照，后续值以源站更新为准。

## 字段与展示

| 源字段 | 本站字段 / 单位 |
| --- | --- |
| tfbh / name / ename | 编号、中文名、英文名 |
| points[].time | 定位时间，显式补 +08:00 |
| lat / lng | 纬度 / 经度，度 |
| power / speed | 风力级别 / 风速 m/s |
| move_dir / move_speed | 移向 / 移速 km/h |
| pressure / strong | 中心气压 hPa / 强度名称 |
| 最新点 forecast[].sets | 预报机构名称，按原值保留 |
| forecast[].points[].time | 预报有效时间 |

预报仅采用最新定位附带的各机构数据。源接口没有单列预报发布时间，`issuedAt` 为 null，`basedOn` 为所附定位时次。不能将采集时间当作气象发布时间。不声称观测出自某一未注明机构，也不猜测风速平均时段。

经纬度图以统一轴范围显示历史点与所选机构预报，未接入地理底图或风圈覆盖图。原演示假海岸和假风圈已移除。源站半径字段保留在快照供以后核验使用，不绘制不确定影响范围。没有地区预警端点；本版本不发布真实地方预警，只显示未接入状态和颜色图例。

## 异常策略

HTTP 超时 20 秒，最多重试 2 次，1/2 秒退避；格式变化、缺少活动状态、编号错配、非法坐标、重复时次或未来实况都视为失败。任何活动台风详情失败使整体失败，防止静默漏报。缺测用 null；0 值保留。JSON 快照先写临时文件再替换。

上次数据优先取公开站点快照，失败才用仓库启动快照。采集失败保留业务数据及最近成功时间，同时更新最近尝试时间与失败状态。无历史可用时发布“尚未取得实况数据”。构建发布后仍把采集异常标记为工作流失败，方便维护者发现。

浏览器每分钟读取相对路径 `./data/latest.json`，不向第三方发起气象 API 请求；第三方返回字符串用 textContent 渲染。45 分钟采集延迟及 6 小时定位陈旧阈值是本站提示策略，不是官方气象有效期。

## 自动化与发布

`.github/workflows/update-and-deploy.yml` 使用每小时第 07、22、37、52 分钟的 UTC 定时配置；时区不影响 15 分钟间隔。同时支持 main 分支相关文件推送和手动触发。执行测试 → 抓取 → 构建 → Pages artifact → Pages 部署。定时数据不写入 Git 历史。

GitHub 定时任务存在调度延迟/丢弃，以及公开仓库 60 天无活动停用限制：[schedule 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。部署方式参见 [Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
